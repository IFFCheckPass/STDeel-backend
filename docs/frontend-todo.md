# 前端配合清单（后端 v2 · 2026-11-01）

> 背景：后端现在要按「知识点」和「解题时间」给你组针对性练习卷。
> 目前落库的 216 条解题记录里 `knowledge_points` 全是空数组，时间也全挤在同一秒，
> 导致只能靠题干文本猜知识点。以下按优先级列出需要前端配合的点，**后端都已支持，不需要等发版**。

---

## P0 · 上传时带上知识点

**接口**：`POST /solve-records`

**形态 A（批量）**：`questions[].knowledge_points` 已经在契约里，但实际同步上来是 `[]`。

```json
{
  "questions": [
    { "id": 18, "content": "…", "knowledge_points": ["直线与圆", "圆的方程"], ... }
  ]
}
```

**形态 B（单条补传）**：契约里没有这个字段，**后端已放宽接收**，带上就会存：

```json
{
  "user_id": "u_5",
  "local_id": 18,
  "question_text": "…",
  "knowledge_points": ["直线与圆"],
  "created_at": "2026-10-20T08:30:00Z"
}
```

**取值要求**

- 直接把 AI 返回的知识点数组原样带上，**不要过滤成空数组**。
- 一条题多个知识点就传多个，组卷时按交集匹配。

---

## P0 · 补传历史记录时带上原始时间

**问题**：一次批量补传 200 多条时，后端只能拿「接收时间」当 `created_at`，
于是所有记录的时间戳都落在同一秒。后端算薄弱点会做「时间衰减」（半衰期 30 天），
时间失真后，三个月前的错题和昨天的错题权重一样。

**改法**：形态 A / B 都加 `created_at`（或 `solved_at`），取本地解题完成时间。

| 接受的格式 | 示例 |
|---|---|
| ISO-8601（推荐，UTC 带 Z） | `"2026-10-20T08:30:00Z"` |
| ISO-8601 带偏移 | `"2026-10-20T16:30:00+08:00"` |
| 秒级时间戳 | `1750000000` |
| 毫秒级时间戳 | `1750000000000` |

后端会做保护：未来时间压回接收时间，2000 年以前视为无效。

## P1 · 知识点写法统一

后端组卷是按**字符串**匹配知识点的，`圆` / `圆的方程` / `直线和圆` 会被当成三个不同的知识点。

建议用教材/题库的章节用词：

```
集合与逻辑   不等式   函数与导数   三角函数   数列
空间向量与立体几何   直线与圆   直线方程   圆锥曲线
概率与统计   复数   平面向量
```

如果 AI 返回的是更细的考点（如「两角和差公式」），建议同时带上**章节级**和**考点级**两个，
例如 `["三角函数", "两角和差公式"]`——组卷时用章节级兜底，用考点级精确匹配。

## P2 · 确认项（现有行为，无需改动）

1. **`questions[].id` 必须稳定**：后端用 `(user_id, local_id)` 做幂等去重，
   同一条记录重复补传时要带同一个本地 id，否则会产生重复行。
2. **`user_feedback` 变更后走 PATCH**：`PATCH /solve-records/{id}/feedback`，
   body `{"feedback": "correct|partial|wrong", "user_id": "u_5"}`，幂等。
3. **可选字段**：补传时带上 `question_no`、`source`、`subject`，后端已接收，
   组卷时能标注「原卷第几题」。
